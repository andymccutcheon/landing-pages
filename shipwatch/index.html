How a briefing is built

What goes in

RSS and Atom feeds, HTML changelog pages, GitHub Releases, and docs sitemaps.

rss
RSS or Atom feeds
html
changelog pages
github
a repository's releases
sitemap
new documentation pages

Every request identifies itself as shipwatch. It reads each site's robots.txt and obeys it unless you turn that off, waits between requests to the same host, and asks for a page again only if it has changed.

shipwatch init writes a starter list of public sources to sources.yaml. Edit it freely. A source is a few lines of YAML.

See the starter source list

What comes out

Outputs are a Markdown file, a JSON file, an RSS feed of past briefings, and an optional static HTML page.

briefing.md
Markdown briefing
briefing.json
structured briefing
briefings.xml
RSS feed of past briefings
index.html
optional static HTML page

The archive is one SQLite file in .shipwatch/. shipwatch has no telemetry of its own.

It is a local pipeline, with no hosted service and no human editor.

What the check does, and what it cannot tell you

A claim that cites no known item is thrown out before the briefing is written.

The verifier takes the claim's content words, four characters or longer, and counts how many appear in the item it cites.

The footer of each briefing reports the counts.

The verifier runs whether or not a model wrote the briefing.

It compares words, not meaning. A sentence that reuses the source's words passes even if it changes a number, adds "not", or turns a price cut into a price rise. Short words and short numbers are not compared at all. Read "supported" as "these words appear in the source", then open the link.

A rubric you can tune

A weighted rubric gives each item and each topic a number from 0 to 1.

Default scoring weights
SignalDefault weightWhat it measures
Novelty0.25how distinct the title is from other items in the window
Impact0.30the kind of item, plus keyword cues
Breadth0.20the audience its text mentions, such as the API, enterprise or all customers
Recency0.25newer items score higher; the default half-life is 7 days

Every weight is a line in shipwatch.yaml. Change them to suit what you cover.

The number tells you how an item did against your rubric. It is not a general measure of importance.

Read the scoring configuration

pricing_change
Pricing changes get an added boost.
deprecation
Deprecations get an added boost.
security
Security items get an added boost.
non_shipment
Case studies, webinars, hiring posts and opinion pieces are tagged as non-shipments and take a penalty.

Quickstart

You need Python 3.10 or newer. No API key and no account.

Install

python -m venv .venv && source .venv/bin/activate
pip install shipwatch

Set up

shipwatch init
shipwatch sources check

Run

shipwatch --no-llm run --since 7d --html

This run requests the public sources in your list. The briefing lands in out/ as briefing.md, briefing.json, briefings.xml and index.html.

Other commands

shipwatch fetch
only updates the archive
shipwatch brief --since 7d
briefs again from what is already stored
shipwatch stats
prints counts

With a model, or without one

Without a model.

No key and no account. Each bullet is a sentence copied from the item: the first usable one, cut at 220 characters.

Some will read as fragments. A copied sentence is being checked against the text it came from, so "supported" tells you little in this mode.

--no-llm

With a model.

Point shipwatch at any OpenAI-compatible endpoint.

export SHIPWATCH_BASE_URL=https://your-endpoint.example/v1
export SHIPWATCH_MODEL=your-model
export SHIPWATCH_API_KEY=...
shipwatch run --since 7d

It asks the model to classify each item, to pull facts from each item, and then to write the briefing. That is two calls for every item in the window, plus one. Count your items before you point it at an endpoint that charges.

In this mode the model writes the headings, and the score printed beside a section is the model's own number when it supplies one.

If the endpoint cannot be reached, or the model's output fails validation after retries, shipwatch writes the copied-sentence briefing instead and says so in a note at the top.

shipwatch has no billing of its own. Tokens go to the endpoint you configure and are billed, if at all, by whoever runs it.

With no endpoint set, shipwatch calls freewhirr on your own machine, a separate tool by the same author; its own page sets out its limits.

Limits

It compares words, not meaning. A flagged claim is not necessarily wrong, and a supported claim is not necessarily right.

No accuracy figure has been measured against a labelled set, and none is published.

HTML extraction
Pages built in the browser extract thinly. An entry with no machine-readable date is left out of every briefing, because shipwatch cannot place it in the week. Use a feed or GitHub Releases where a site offers one.
Keyword rules
The signals are keyword rules. They will tag some posts wrongly, and a post the rules do not recognise is scored as "other".
Near-duplicates
Items with the same link, or mostly the same words, are merged. The comparison is by shared words, so one release described in different words can appear twice.
Source addresses
Source addresses move. Run shipwatch sources check --live after you edit the list.

Only if you use a model, the titles and text of fetched items go to the endpoint you configured.

shipwatch looks for the key variable you configured, then OPENROUTER_API_KEY, then OPENAI_API_KEY, and sends the first one it finds to your endpoint. Keep only the key for the endpoint you are using in that shell.

For HTML changelogs, the link on a bullet is the first link found inside the entry. Sometimes that is a docs page the entry points to, not the changelog itself.

A blocked, unreachable or unparseable source is reported by name in the run output. The other sources still run.

Status

shipwatch is version 0.1.1, an early release under the MIT licence. It is maintained by one person. Issues and pull requests are welcome.

It drafts; it does not edit. If you need a briefing nobody has to check, this is the wrong tool.
