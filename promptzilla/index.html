01 / The loop

Four passes. One gate.

A raw request becomes a System Prompt and a Task Prompt. Judge scores them. Revise rewrites. Judge scores again. Only a 9 or 10 stops the loop.

Judge
09/10

STOP / approved

    Generate

    One request becomes two prompts: a System Prompt and a Task Prompt.

  2. 02

    Judge

    Score

    A locked 0 to 10 rubric, quoted evidence, and numbered recommendations.

  3. 03

    Revise

    Rewrite

    Applies every recommendation and cuts nothing that was not asked for.

  4. 04

    Judge

    Re-score

    Scores the exact rewritten body. At 9 or above, the loop stops.

The pipeline caps at four scoring rounds. A plateau pauses for your decision. It never invents a score.

02 / The method

Five skills, each with a narrow job.

Every skill has a boundary. None of them does the others' work.

  1. 01

    Brief

    Turns a rough free-form task into an execution-ready instruction for another agent. Unknowns become bracketed placeholders.

    Refuses to perform the task.

  2. 02

    Compose

    Turns a raw request into two prompts, a System Prompt and a Task Prompt, with every required heading from the source skill.

    Refuses to execute the task.

  3. 03

    Judge

    Scores a prompt on a locked 0 to 10 rubric with quoted evidence, one overall rating, a STOP or CONTINUE verdict, and numbered recommendations.

    Refuses to rewrite the prompt.

  4. 04

    Revise

    Rewrites a prompt by applying every numbered recommendation. It returns the complete rewrite and a checklist for every recommendation.

    Refuses to cut what was not asked for.

  5. 05

    Loop

    Runs Compose, Judge, and Revise in order until Judge says STOP, within four scoring rounds.

    Refuses to score or rewrite itself.

One command installs all five into Claude Code, OpenCode, and shared agents.

03 / What leaves

A prompt you can read, not a chat log.

Every run is a directory. The stages, scorecards, retries, and final prompt stay on disk.

./prompts/final output
meeting-notes.md            9/10  approved
release-notes.md            8/10  provisional

runs/4cd2abf2-51ec-462d-a4eb-6155be65f94c/
  00-request.md
  01-compose.md
  02-judge-pass1.md
  03-revise.md
  04-judge-pass2.md
  05-final.md

The filename comes from your request. The file contains the prompt itself, with no frontmatter and no commentary.

Approved

STOP at 9 or above.

The scored prompt is written to <slug>.md and marked approved.

Provisional

A cap, a block, or a plateau.

The best scored candidate is written to <slug>.provisional.md and clearly marked not approved.

Paused

No improvement after two rewrites.

The run waits for your decision. Continue with run --resume <id> --decision "...".

04 / Bring your own model

Use the model you already trust.

Each stage runs in a fresh process. Promptzilla stores no credentials; the worker you choose handles its own authentication.

npx promptzilla run --prompt ./prompt.md --worker opencode

The default worker. Add --model to choose a model.

npx promptzilla run --prompt ./prompt.md --worker claude --model claude-sonnet-4-5

Uses claude -p in a fresh process for every stage.

npx promptzilla run --prompt ./prompt.md --worker codex

Uses codex exec in a fresh process for every stage.

Install the five skills

npx promptzilla install

Detects Claude Code, OpenCode, and shared agents. Use --target or --dir when you want control.

Prefer to drive each stage yourself? 
promptzilla start --request "Write a prompt for a meeting-notes summarizer"
promptzilla submit <run-id> --dispatch <id> --output stage.md
promptzilla status <run-id>

The run records every stage, scorecard, and retry. status --json returns the next dispatch.

05 / Boundaries

What it does not do.

The honest limits are part of the product.

01

It does not call a model.

The worker does. Promptzilla needs no API key and stores no credentials.

02

It does not run an agent.

It prepares packets, validates the returned output, and records the run. In manual mode, your host provides the isolation.

03

It checks structure, not truth.

Scorecards are validated for shape and consistency, not semantic truth, completeness of evidence, or model quality.

04

It does not apply fixes silently.

Exact replacements are explicit, all-or-nothing, and confirmed by a fresh Judge before approval.
