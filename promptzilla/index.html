MCP server · five prompt-engineering skills

A prompt pipeline your AI client runs.

Write the request. Promptzilla generates the prompt, scores it on a locked rubric, rewrites it against the numbered recommendations, and stops when the score reaches 9. You do not build the loop.

The connected AI client executes the skills, so there is no API key and no model-provider account.

What each stage is allowed to do

Tasker

Turns a rough free-form task into an execution-ready instruction for another agent. Unknowns become bracketed placeholders. It never performs the task.

skills/tasker

Metapod

Turns a raw request into two prompts, a System Prompt and a Task Prompt, with all 11 System headings and all 4 Task headings from the source skill. It never executes the task.

skills/metapod

Judge Dredd

Scores a system prompt on a locked 0 to 10 rubric with quoted evidence, then returns section ratings, one overall rating, a STOP or CONTINUE verdict and numbered recommendations. It evaluates only.

skills/judge-dredd

Brian Spillner

Rewrites a prompt applying every numbered recommendation, cutting nothing that was not asked for, and returns the full rewrite plus a line for every recommendation marked applied or deferred.

skills/brian-spillner

Prompt Pipeline

Runs Metapod, then Judge Dredd, then Brian Spillner until Judge says STOP at an overall rating of 9 or above, with at most four scoring rounds. It orchestrates only.

skills/prompt-pipeline

Three ways a run ends

A run is finished when the rubric says so, when the loop limit is reached, or when the rewrite stops improving and the decision is yours. Promptzilla reports which of the three happened.

STOP at 9 or above
The scored prompt is approved and written as the final artifact.
Four-round cap
The best scored candidate can be exported as provisional, with approved set to false.
No improvement
After two rewrites without improvement the run pauses and asks you the actual question.

Pass 1 counts toward the four-round maximum.

Start from a request, or from the prompt you already have

full

Starts at Metapod from a raw request. The request is saved as the run's first file, then generation, scoring and rewriting follow.

optimize-only

Saves your existing prompt byte for byte and starts at Judge. Interior whitespace, Unicode, trailing spaces and line endings are preserved.

Read the README

Every run is a directory you can read

A run is not a chat log. It is a folder of Markdown stage files plus run.json, written with private permissions as the pipeline advances.

Artifacts are immutable. Changed stage files are detected, and missing derived files are reconstructed from run.json. Call pipeline_status with the run's identifier to pick a run up after a server restart.

Runs are stored under your home directory by default.

What Promptzilla does not do

It does not run an agent for you. Standalone tools return instructions and input packets. They do not secretly call an LLM, and the server cannot create isolated AI workers itself.

Fresh context is your host's job.

Running each stage in a genuinely fresh worker is the host's obligation. The server records what the host attests, validates returned output, enforces the loop limits and rejects reused execution identifiers.

A unique identifier and a fresh-context flag are recorded attestations. They are not a technical sandbox, and they are not proof of separate model execution. A host without fresh-context workers has to pause the run with a blocker.

It checks structure, not truth.

Scorecards are validated for structure and consistency. They are not validated for semantic truth, completeness of evidence or model quality. Structural acceptance does not verify that a rewrite preserved every fact or implemented its recommendations: those remain duties of the worker and of Judge.

Fixes are explicit.

Exact fixes are never inferred from a scorecard. Each pair has to match a quoted replacement in a Judge recommendation and occur exactly once. All of them succeed or none are written, and the result stays unapproved until a fresh Judge confirms the diff.

Your prompt text stays on your disk.

Run data stays on disk until you remove it, and it can contain your prompt text. The server itself does not send prompt data to external services. This is a single-user service over standard input and output, with filesystem permissions as its access boundary.

Status

Promptzilla is version 1.0.0 on npm under the MIT licence. Continuous integration runs on Node 22, 24 and 26.

It can also run as a private, authenticated HTTP server on your own Cloudflare account, using Workers and Durable Objects with no database and no model API. The repository's Cloudflare guide covers that path.
