MCP server / five prompt-engineering skills

Stop hand-writing your prompts.

Your AI client drafts the prompt, scores it on a locked rubric and rewrites it. Only a 9 or 10 passes.

What each stage is allowed to do

SkillWhat it doesBoundary
Taskerskills/taskerTurns a rough free-form task into an execution-ready instruction for another agent. Unknowns become bracketed placeholders.Never performs the task.
Metapodskills/metapodTurns a raw request into two prompts, a System Prompt and a Task Prompt, with all 11 System headings and all 4 Task headings from the source skill.Never executes the task.
Judge Dreddskills/judge-dreddScores a system prompt on a locked 0 to 10 rubric with quoted evidence, then returns section ratings, one overall rating, a STOP or CONTINUE verdict and numbered recommendations.Evaluates only.
Brian Spillnerskills/brian-spillnerRewrites a prompt applying every numbered recommendation and returns the full rewrite plus a line for every recommendation marked applied or deferred. Interior whitespace, Unicode, trailing spaces and line endings are preserved.Cuts nothing that was not asked for.
Prompt Pipelineskills/prompt-pipelineRuns Metapod, then Judge Dredd, then Brian Spillner until Judge says STOP at an overall rating of 9 or above, with at most four scoring rounds.Orchestrates only.

How a run ends

Approved by the rubric, stopped by the loop limit, or handed back to you. Promptzilla records which one happened.

Approved
STOP at 9 or above. The scored prompt is approved and written as the final artifact.
Provisional
Four-round cap. The best scored candidate can be exported as provisional, with approved set to false.
Paused
No improvement. After two rewrites without improvement the run pauses for your decision.
Blocked
Rejected twice. A stage output rejected twice blocks the run. If there is a best scored candidate, it can still be exported as provisional.

Pass 1 counts toward the four-round maximum.

Start from a request, or from the prompt you already have

full

Starts at Metapod from a raw request. The request is saved as the run's first file, then generation, scoring and rewriting follow.

optimize-only

Saves your existing prompt to 00-original.md byte for byte, unchanged, and starts at Judge instead of Metapod.

Install

You need Node.js 22.12 or newer. No API key and no account.

Claude Code

claude mcp add promptzilla -- npx -y promptzilla

Claude Desktop, Cursor, any MCP client

      "command": "npx",
      "args": ["-y", "promptzilla"]
    }
  }
}

Every run is a directory you can read

A run is not a chat log. It is a folder of Markdown stage files plus run.json, written with private permissions as the pipeline advances.

Artifacts are immutable. Changed stage files are detected, and missing derived files are reconstructed from run.json. Call pipeline_status with the run's identifier to pick a run up after a server restart. Runs are stored under your home directory by default.

A full run, stage by stage
FileContents
00-request.mdThe raw request, or 00-original.md for an optimize-only run
01-metapod.mdThe generated System and Task Prompts
02-judge-pass1.mdThe first scorecard and its verdict
03-brian-rewrite.mdThe rewrite and its recommendation checklist
04-judge-pass2.mdThe re-score of the rewritten body
05-final.mdThe approved prompt, or 05-provisional.md at a cap

What Promptzilla does not do

Boundary

It does not run an agent for you.

Standalone tools return instructions and input packets. They do not secretly call an LLM, and the server cannot create isolated AI workers itself.

Host

Fresh context is your host's job.

Running each stage in a genuinely fresh worker is the host's obligation. The server records what the host attests, validates returned output, enforces the loop limits and rejects reused execution identifiers.

A unique identifier and a fresh-context flag are recorded attestations. They are not a technical sandbox, and they are not proof of separate model execution. A host without fresh-context workers has to pause the run with a blocker.

Scoring

It checks structure, not truth.

Scorecards are validated for structure and consistency. They are not validated for semantic truth, completeness of evidence or model quality. Structural acceptance does not verify that a rewrite preserved every fact or implemented its recommendations: those remain duties of the worker and of Judge.

Fixes

Fixes are explicit.

Exact fixes are never inferred from a scorecard. Each pair has to match a quoted replacement in a Judge recommendation and occur exactly once. All of them succeed or none are written, and the result stays unapproved until a fresh Judge confirms the diff.

Data

Your prompt text stays on your disk.

Run data stays on disk until you remove it, and it can contain your prompt text. The server itself does not send prompt data to external services. This is a single-user service over standard input and output, with filesystem permissions as its access boundary.

Status

Promptzilla is version 1.0.0 on npm under the MIT license. Continuous integration runs on Node 22, 24 and 26.

It can also run as a private, authenticated HTTP server on your own Cloudflare account, using Workers and Durable Objects with no database and no model API. The repository's Cloudflare guide covers that path.
