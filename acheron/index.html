Tool sprawl hides the note that answers the question

Agents wired to a personal knowledge base hit two problems.

Too many tools.

Basic Memory's own MCP server exposes around 27 tools, including two overlapping search verbs. Every turn the agent has to choose, and the weaker path is always selectable.

search_notes search

Ordering is not recall.

Hybrid search finds the right notes, but hub pages, person pages and passing mentions outrank the note that answers the question. On the demo set in the repository, native search put the expected note first in 7 of 16 questions.

That figure comes from 23 synthetic notes and 16 hand-labelled questions. It shows the shape of the problem, not its size on your notes.

How a question becomes a ranked answer

Every response says how it was ranked, so the agent can tell a reranked answer from a fallback.

Read the steps as text
  1. The demo corpus, indexed. Twenty-three markdown notes for a fictional photo-sync project, grouped by folder. Basic Memory keeps a local hybrid index over them and refreshes when files change.
  2. A question arrives. Any agent calls the one first-party tool, context_search. Every other storage tool stays proxied under its engine name.
  3. Hybrid search on the engine. Acheron forwards search_notes to the long-running Basic Memory service. Candidates come from the engine's native hybrid search, not from the decision model.
  4. Ten candidates return. Up to ten notes return with paths and snippets. The right answer is usually already in the list; reranking only reorders.
  5. The model scores each note. When an OpenRouter key is set, Mercury Decide scores each candidate on usefulness. Note text is untrusted evidence, not instructions.
  6. Scores return. Scores are ordering signal. They do not change which notes were retrieved; the score labels shown here are illustrative.
  7. Model order wins. In auto mode with Mercury, model order wins. On the unstacked benchmark (16 questions, 23 synthetic notes, hand labels), Mercury put the labeled note first in 14 of 16; native hybrid alone reached 7 of 16.
  8. Results reach the agent. The response lists ranked notes with paths and snippets so the agent can open the winner. One call, no search loop.
  9. When the model rate-limits. A 429 from the Decisions API is a reranker failure, not a storage outage. Acheron does not pretend the engine survived an outage.
  10. One retry. The client waits, then retries once on 429 or 5xx. A persistent outage still fails open after that.
  11. Native order, fallback true. If the model stays down, results keep native hybrid order. The response sets fallback: true and ranking: native. Recall stays; ordering weakens.
  1. The agent calls one tool. context_search is the only search verb. It takes a query, the engine's filters, or both.
  2. Basic Memory returns candidates. Acheron asks the engine for its native hybrid results, ten by default.
  3. A decision model re-orders them. Each candidate is scored against the question on a four-step scale, from "unrelated" to "direct answer".
  4. If the model fails, you still get an answer. Results come back in the engine's native order, marked fallback: true.
  5. Filters alone skip the model. Ask by tag, status or date with no query and you get native order, marked ranking: "native".

The sample is illustrative. It shows the response fields without quoting the explainer's on-screen numbers.

{
  "query": "how do we handle sync conflicts?",
  "ranking": "model",
  "fallback": false
}

One surface, and nothing renamed

Acheron discovers the engine's tools when it starts and passes them through under their original names, with their parameter schemas and safety annotations intact. Your client's permission prompts keep working.

Three tools are hidden. search_notes is folded into context_search, because two search tools means a decision on every turn. search and fetch are adapters for ChatGPT connectors and do nothing for other clients.

Remove Basic Memory's own entry from your client's configuration. Acheron proxies it.

When it goes wrong, and what leaves your machine

The ranking model fails.

Acheron retries once on a rate limit or server error. After that, or with no key set, results come back in native order with fallback: true. This covers the reranker only. If Basic Memory itself is down, search returns an error.

One retry, then native order

A call asks for too much.

Results are capped at 25 and candidates at 50 per call, and the rerank timeout is bounded. One request cannot inflate payload size or provider usage.

25 results, 50 candidates, bounded timeout

A note contains instructions.

Note text reaches the ranking model labelled as untrusted evidence to score, not instructions to follow, and the search tool tells your agent the same. This is a prompt-level guard, not isolation. Keep your client's tool permissions on.

Untrusted evidence to score, not instructions to follow

What is sent out.

By default, a search with a query sends that query, each candidate's title and up to 500 characters of each candidate's text to OpenRouter for scoring. Unless you name a project, the search covers every project you have registered. Filter-only searches make no model call.

Query, candidate titles, up to 500 characters per candidate

Turning it off.

Set ACHERON_PROVIDER=none and reranking is off: no key, no outbound call, native order.

No key, no outbound call, native order

Where the key comes from.

Acheron uses OPENROUTER_API_KEY if it is set. Otherwise it reuses the OpenRouter key that OpenCode stores on your machine, if there is one.

Environment first, then OpenCode

Read the design notes

Your notes stay plain markdown

This part is Basic Memory's design, and Acheron leaves it alone. Your notes are ordinary markdown files in ordinary folders. The search index and the graph of links between notes are built from those files and can be rebuilt from them. Anything that writes markdown is a valid way to add a note.

Save a note and your agent can find it in under a minute.

Quickstart

You need Python 3.12 or newer, uv, and Basic Memory with a project of markdown notes. For reranking you also need an OpenRouter key. Without one the server still works and returns native order. Acheron is not on PyPI, so clone the repository first.

Run the servers

$ uv sync
scripts/start-bm-http.sh     # Basic Memory's HTTP MCP service on port 8765
uv run acheron               # the one agent-facing server (stdio)

Claude Code

$ claude mcp add --scope user acheron -- /path/to/acheron/.venv/bin/acheron

OpenCode (~/.config/opencode/opencode.jsonc)

"acheron": {
  "type": "local",
  "command": ["uv", "run", "--directory", "/path/to/acheron", "acheron"],
  "enabled": true
}

Do not also configure Basic Memory's own MCP entry. Acheron proxies it.

Status

Acheron is a reference implementation. There is no support promise and no maintenance guarantee. Issues and pull requests are welcome on a best-effort basis.

The code targets Basic Memory's HTTP MCP server. There is no adapter for other storage engines. The part meant to travel is the pattern: discover the engine's tools, hide the duplicate search verb, proxy the rest unchanged, and rerank with a fallback.
