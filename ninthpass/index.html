Prompt review, enforced in code

Give your agents best-in-class prompts.

A separate process that never saw the write scores your prompt against a locked twelve-section rubric, quotes the line that cost the points, and rewrites it until it clears 9. The scorecard stays on disk beside the prompt.

01 / The shortcut

You can already ask the model to grade its own homework.

Ask it to write the prompt, then ask it in the same conversation what is wrong with it. It is free, it is instant, and it works often enough to stay the default. Three things are missing from it.

What the shortcut cannot do

  1. No record.

    The grade lives in a chat window. Nothing shows what changed, or why, and nothing is left behind to check later.

  2. No teeth.

    Nothing stops it shipping at 6. The verdict is a sentence in a transcript, so the prompt goes out exactly as written.

  3. No separation.

    The critic holds the writer's context in the same window. A model grading the work it just did is a compliment, not a grade.

What Ninth Pass does instead

  1. A separate process.

    Judge never saw the draft it grades. Every stage runs in a fresh process with no memory of the last one.

  2. Quoted evidence.

    Every section rating has to quote the line that cost the points. A rating with nothing after the dash is rejected by the code.

  3. A gate in the code.

    Below 9 the file is written as provisional and never as the prompt. A 9 or a 10 stops the loop; the score and the verdict have to agree or the scorecard is malformed.

02 / Boundaries

What it does not do.

A score of 9 is a judgement about a prompt's structure. It is not a certificate that the answer will be right.

01

It does not call a model.

The worker does. Ninth Pass needs no API key and stores no credentials.

02

It does not run an agent.

It prepares packets, validates the returned output, and records the run. In manual mode, your host provides the isolation.

03

It checks structure, not truth.

Scorecards are validated for shape and consistency, not semantic truth, completeness of evidence, or model quality.

04

No human signs off.

Approval is the code accepting a 9 and writing the file. Judge is a model scoring against a fixed rubric.

03 / The standard

Best-in-class is twelve sections.

It is not an adjective. It is a fixed rubric, and every one of its ratings has to quote the line that cost the points. These are the ratings from the run above, unedited.

  1. Primary Role 9

    "You are a professional meeting summarizer who distills lengthy discussions into actionable, executive-ready bullet points" is specific,…

  2. High-Level Objectives 8

    Four clear objectives present ("Extract the most critical information", "Identify decisions, action items"), though success criteria could be more…

  3. Domain Expertise & Resources 7

    Lists relevant domains ("Corporate communication best practices", "Meeting facilitation") but remains outline-level without when-to-apply guidance

  4. Allowed Tools & APIs 7

    States "Text processing and summarization. No external tools required" clearly but minimally

  5. Operating Constraints 9

    Hard rule "Output must be exactly five bullet points" is specific and enforceable; includes edge case handling ("When input lacks five distinct…

  6. Interaction Style & Voice 8

    Multiple specific directives ("Use active voice and strong verbs", "Write for busy executives who scan") provide clear guidance

  7. Memory & Context Handling 7

    Present ("Retain context about ongoing meetings") but outline-only; lacks specifics on how to handle multi-session contexts

  8. Self-Monitoring & Reflection 8

    Three concrete checks listed ("Verify all five bullets represent distinct information"), could include verification of factual accuracy

  9. Example Exchanges (Few-Shot) 9

    Three examples covering standard case, edge case (empty meeting), and draft request scenario with realistic detail

  10. Safety & Ethics 8

    Four clear directives including "Never fabricate information not present in source material" and confidentiality guidance

  11. Deliverable Structure 9

    Exact format specified with bullet structure requirements ("Beginning with a strong action verb", "Containing one primary idea")

  12. Task Prompt 8

    Clear GOAL and RETURN FORMAT sections, though redundant with system prompt Operating Constraints and Deliverable Structure

Twelve sections, scored 0 to 10, one overall rating, one verdict. The rubric is locked: a scorecard that disagrees with itself is rejected before it reaches disk. Read the scorecards in full.

05 / The loop

Four passes. One gate.

A raw request becomes a System Prompt and a Task Prompt. Judge scores them. Revise rewrites. Judge scores again. Only a 9 or a 10 stops the loop. This is the run above, replayed.

    One request becomes two prompts: a System Prompt and a Task Prompt.

  2. 02

  3. 03

    Rewrite

    Applies every recommendation and cuts nothing that was not asked for.

    Scores the exact rewritten body. The score did not move, so the loop kept going.

    Rewrite again

    A second rewrite inside the same round, after a round that did not improve.

  6. 04b

    Judge

    Final pass

    9 out of 10. The loop stops and the prompt is written to disk.

The pipeline caps at four scoring rounds. A plateau pauses for your decision. It never invents a score.

06 / Bring your own model

Use the model you already trust.

Each stage runs in a fresh process. Ninth Pass stores no credentials; the worker you choose handles its own authentication.

node dist/cli.js run --request "Write a prompt for a meeting-notes summarizer" --worker opencode

The default worker. Add --model to choose a model.

node dist/cli.js run --request "Write a prompt for a meeting-notes summarizer" --worker claude

Uses claude -p in a fresh process for every stage.

node dist/cli.js run --request "Write a prompt for a meeting-notes summarizer" --worker codex

Uses codex exec in a fresh process for every stage.

Install the five skills

node dist/cli.js install

Detects Claude Code, OpenCode, and shared agents. Use --target or --dir when you want control. npm install -g ninthpass once the package is on npm.

Prefer to drive each stage yourself? 
node dist/cli.js start --request "Write a prompt for a meeting-notes summarizer"
node dist/cli.js submit <run-id> --dispatch <id> --output stage.md
node dist/cli.js status <run-id>

The run records every stage, scorecard, and retry. status --json returns the next dispatch.
